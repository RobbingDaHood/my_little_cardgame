# Vision & Roadmap Suggestions from B2.5 Herbalism Simulation

## Context

These suggestions are based on the B2.5 herbalism balance simulation work — rebasing onto the DisciplineDriver pattern from PR #61, and tuning herbalism config to hit the 0.2–0.4 yield/durability target.

## Suggestions for `docs/vision/vision.md`

### Add DisciplineDriver as an architecture concept

The `DisciplineDriver` trait (introduced in B2.4/mining, now used by herbalism) is emerging as a core testing architecture pattern. Consider documenting it in vision.md under testing philosophy:

> Balance simulations use a shared `DisciplineDriver` trait that separates discipline-specific logic (encounter selection, card play, yield tracking) from shared infrastructure (game lifecycle, death handling, scouting, strategy dispatch). This enables rapid addition of new discipline simulations with minimal boilerplate.

### Add cross-discipline yield parity as a first-class design goal

Vision.md should explicitly state that all gathering disciplines target the same yield/durability ratio (0.2–0.4). This is already in the balance docs but deserves prominence in the vision as a design principle.

## Suggestions for `docs/vision/roadmap.md`

### Update B2.5 status

B2.5 (Herbalism simulation runner) should be marked as complete:
- Herbalism simulation runner implemented using DisciplineDriver pattern
- Config tuned to 0.2–0.4 yield/durability target (all 4 strategies in range)
- Balance doc updated with observed results

### Update B2.4 status

If not already done, B2.4 (Mining simulation runner / DisciplineDriver introduction) should be marked as complete (merged as PR #61).

### Add B3 strategy differentiation milestone

Current B2.x items focus on getting each discipline within the 0.2–0.4 band. However, the herbalism results show that **strategy differentiation is modest** — tactician (0.345) only slightly outperforms simple strategies (0.23–0.34). The balance doc says tactician should "reliably land in the upper half" and the gap should be "meaningful."

Consider adding a B3 milestone for:
- Tuning match mode cost differentials to widen the tactician vs simple strategy gap
- Ensuring tactician reliably lands in 0.3–0.4 while simple strategies land in 0.2–0.3
- Cross-discipline strategy differentiation consistency

### Note DisciplineDriver reuse pattern for remaining B2.x items

B2.6 (Woodcutting), B2.7 (Fishing), etc. should note that they will follow the same DisciplineDriver pattern, making implementation faster. Estimated effort per remaining gathering discipline is significantly reduced now that the shared infrastructure exists.

### Consider reducing CI simulation size documentation

During tuning, 3-game simulations showed high RNG variance (e.g., random strategy swinging from 0.168 to 0.384). The 5-game default provides a good balance of CI speed (~8s) and stability. This tradeoff should be documented in the roadmap or balance methodology section.
